# 一致性机制

## 强一致读（豁免）

缓存是最终一致的。需要强一致的场景按档位选用：

| 档位 | 用法 | 适用 |
|---|---|---|
| 自定义方法不加注解 | `selectByIdFromDb(Long id)` | 已知某方法永远要 DB |
| ThreadLocal 旁路 | `CacheKit.withDb(() -> mapper.selectById(id))` | 调用点临时决定 |
| SpEL 条件 | `@CachedQuery(condition = "!forceDb")` | 由调用方传参决定 |

**库存扣减、余额等强一致判断所依赖的字段不要进缓存**——任何缓存方案（双删、binlog 均不例外）都是最终一致。

## 一致性机制

写路径固定**先写 DB 后删缓存**（Cache-Aside 标准序）。删除动作 = **DEL L2 → 本地 L1 → 广播 → 延迟双删**。
顺序关键：必须先删 L2——若先删 L1，间隙内并发读会 L1 miss 后从 L2 读到旧值并回填 L1，制造可复现脏数据。

脏数据的核心窗口是**回填竞态**（读线程查到旧值、写线程删除后、读线程把旧值回填进 L1/L2）。
延迟双删压缩该窗口；窗口之外（慢读/长 GC 跨过双删间隔、双删积压丢弃、Redis 宕机期间失效丢失）
旧值可能复活在 L2 并持续回填各节点 L1，此类场景的真实上界是 **L2 TTL（默认 10m + 抖动）**，
而非秒级——这是 Cache-Aside 的固有竞态，本组件未用版本号/CAS 消除它，依赖 TTL 上界兜底。
对一致性敏感的字段请用 `CacheKit.withDb` 旁路或直接不进缓存。

## 失效广播通道选择（0.3.1+）

| | `pubsub`（默认） | `streams` |
|---|---|---|
| 投递语义 | fire-and-forget：订阅方掉线/网络抖动即丢失，靠 L1 TTL 兜底 | 消费组 ACK：实例短暂掉线不丢失效，恢复后补投 |
| Redis 侧开销 | 零存储 | 一份 Stream 数据（`MAXLEN ~ streams-maxlen` 近似裁剪，默认 10000） |
| 每实例状态 | 无 | 一个独立消费组（优雅停机自毁；崩溃残留由存活实例周期清理） |
| 送达延迟实测 | 2 实例 × 200 键 202ms 全送达 | 3 实例 × 500 键 157ms 零丢失 |

单实例（无 L1 一致性需求）或可容忍秒级 TTL 兜底时用默认 pubsub；多实例且对"重启窗口丢失效"敏感时用 streams。

**streams 模式的运维边界（K8s 弹性伸缩前必读）**：

- **消费组清理周期与最坏残留**：存活实例每 5 分钟扫一次；判定条件 = 组名内嵌纪元超过 30 分钟
  **且**组内无消费者或全部闲置超 10 分钟（健康消费者闲置至多 5s，不会误杀）。
  崩溃实例的组最坏残留 **~40 分钟**（30min 纪元豁免 + 10min 闲置判定 + 5min 扫描间隔）。
  残留组无害：不阻塞 Stream 裁剪，只是组元数据 + PEL 引用。
- **新实例与旧组**：组名内嵌 `进程纪元 + UUID`，新实例永远创建自己的组（从 `$` 最新位置起读，
  启动时 L1 为空不需要历史消息），与旧组零冲突。
- **组丢失自愈（0.3.3+）**：Redis 重启/FLUSHALL/主从切到空实例/Stream 键被淘汰时组会消失。
  消费者检测到 `NOGROUP` 后原地重建：首次启动仍从 `$` 读，运行中组丢失则从 `0-0` 重放当前
  保留的 Stream（总量受 `streams-maxlen` 约束），尽量补投组丢失期间的消息；重放是幂等 DEL，
  已过期的消息由 L1 TTL 兜底。计数 `cache-kit.broadcast.streams.group.recreated`。
- **真实丢失面**：`MAXLEN ~ streams-maxlen`（默认 10000）裁剪作用于整个 Stream——
  某实例的消费组落后超过该条数时，落后部分对它永久丢失（等价 pubsub 丢消息，L1 TTL 兜底）。
  实例离线时长 × 写失效速率超过 streams-maxlen 时，streams 退化为 pubsub 语义。
- **扩缩容频繁时**：每个副本世代产生一个组，组数量 ≈ 滚动窗口 40 分钟内的世代数 × 副本数，
  元数据极小但建议纳入观测（`XINFO GROUPS <topic>`，或对 Redis 侧内存设基线告警）。
  发布频率极高（分钟级滚动）且实例数大时，优先评估 pubsub + 更短的 L1 TTL 组合。

## 性能量级（摘要）

- 本地 L1 命中路径为亚微秒~微秒级；有本地层的实现吞吐上限远高于纯远程（Redis 往返 + 连接池）实现。
- 工作集超出 L1 后，吞吐回落到远程量级；有效容量由 L1 容量、TTL 与访问倾斜决定的命中率支配。
- single-flight 使每键回源收敛为 1 次；无单飞语义的实现击穿时回源次数约等于并发数。
- 跨实例失效广播延迟为几十毫秒级；pubsub 可能丢消息、streams 有消费组滞后与 MAXLEN 边界，均由 L1 TTL 兜底。
- 完整的压测方法、原始数据、逐项归因与 PaperWise 生产实测已归档到维护文档，不随组件仓库发布。
